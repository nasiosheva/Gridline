# Implementasi M3 Grid Pane — 2026-10-23

## Scope

Implementasi ini mengerjakan langkah 10–15 M3: grid 1–4 pane, divider antar-pane, preset toolbar, fokus keyboard, batas ukuran minimum, maksimalisasi pane, mode terminal-only, penanda perhatian proses terminal, penutupan repo dengan pemulihan lewat toast, placeholder pemulihan repo, dan dukungan identitas worktree.

## Struktur

- `PaneLayout` dan `PaneSlot` menyimpan referensi repo, pane aktif, split atas/bawah per pane, serta posisi divider antar-pane. Model ini tidak memiliki terminal, diff, atau viewer.
- `AppStateStore` memigrasikan state M1 (`activeRepoID` dan satu `paneSplitTopFraction`) ke format layout baru dan tetap menulis JSON secara atomik. Perubahan divider grid dipersistenkan dengan debounce 250 ms.
- `NestedPaneSplitView` meng-host isi SwiftUI melalui `NSHostingController` dan menyusun `NSSplitViewController` secara bertingkat. Dua pane disusun sebagai dua kolom; tiga/empat pane memakai dua baris dengan split kolom pada baris yang memerlukannya.
- `ContentView` memasok environment registry ke setiap hosting controller, menandai pane aktif, dan mempertahankan ukuran minimum melalui area scroll saat jendela terlalu kecil.
- `GridlineApp` menyediakan pintasan ⌘1–⌘4 dan ⌥⌘+panah melalui menu macOS.
- `RepoPaneView` dan `RepoPaneHeaderView` menyediakan tombol maksimalisasi pane serta terminal-only; shortcut ⌃⌘M dan ⌥⌘M mengubah mode pane aktif melalui `AppStateStore`.
- Mode maksimalisasi hanya mengubah rendering. Registry sesi repo yang tidak tampil tetap hidup, sehingga proses terminal tidak dihentikan.
- `TerminalTab` meneruskan exit code ke `RepoSession`; status selesai/gagal ditampilkan di header pane dan diringkas di toolbar. Status dibersihkan ketika pane difokuskan.
- Tombol × dan ⌘⇧W melepas referensi repo dari pane, sementara `RepoSessionStore` tetap mempertahankan sesi. Toast "Repo ditutup · Buka lagi" memulihkan repo ke pane asal.
- Pane kosong menawarkan hingga tiga repo terakhir. Path repo yang tidak lagi ada di disk menampilkan peringatan dan aksi cari ulang folder; state layout dan frame tetap memakai persistence yang sudah ada.
- Verifikasi model worktree membuat dua folder dengan `.git` berupa file pointer dan memastikan keduanya valid serta mendapat identitas `Repo` berbeda; uji dua pane runtime menunggu build GUI.

## Kompatibilitas State

State format naik dari versi 1 ke versi 2. Saat membuka state lama, repo aktif ditempatkan di slot pertama, slot kedua dibuat kosong sesuai default dua kolom, dan nilai split atas/bawah lama diterapkan pada kedua slot. Encoding versi 2 tidak lagi menulis kunci lama.
